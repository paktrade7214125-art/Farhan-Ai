# Architecture Decision Records

Store meaningful architecture decisions in this folder. Do not create records for decisions that have not actually been made. A decision can be proposed until validated against the repository and user requirements.

## Record template
- **ID and title:** ADR-NNN — concise title
- **Date:**
- **Status:** Proposed / Accepted / Superseded
- **Context:** problem and constraints
- **Alternatives considered:** include trade-offs
- **Decision:** chosen approach
- **Reasons:** why it fits
- **Consequences:** benefits, costs, follow-up work
- **Security implications:** threat and mitigation notes

## Initial decisions to validate
The current product brief proposes Electron, a narrow preload bridge, provider adapters, JSON-based initial persistence, and a workspace-restricted tool registry. These are proposed architectural directions, not proof that the repository already implements them. Create an ADR when a decision is confirmed or a meaningful alternative is evaluated.
